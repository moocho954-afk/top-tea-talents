# TOP TEA TALENTS — Public Web App

Public, sign-up-working home for **TOP TEA TALENTS** (parent brand PhantomDreamsz).
Mission: CASTING • DISCOVERY • BOOKINGS • OPPORTUNITY. South Florida first,
then Florida, then nationwide.

**TEST MODE is on.** Submissions are paused, nothing is ever sent live,
no payments are collected. Commissions are calculated and tracked only.

## Architecture — free tier only ($0)

| Piece | Where | Cost |
|---|---|---|
| Frontend (static SPA, no build step) | GitHub Pages | $0 |
| Backend API (Bun + TypeScript, zero runtime deps) | Render free tier, Docker | $0 |
| Database | Turso (libSQL, free tier) — durable | $0 |
| Database fallback | Render local SQLite — **demo only, wipes on restart** | $0 |

The frontend talks to the backend through `window.__TTT_API__`, written by the
Pages workflow from the repo variable `TTT_API_URL`. No API URL is hardcoded.

## What the platform does

- **Talent registration** — 3-screen JOIN wizard (v7: screen 1 quick —
  name, email, phone, password, city, state dropdown, contact
  preference, terms — creates the account at once; remaining fields
  moved to post-signup profile completion with a % meter on the
  dashboard). Email verification: 6-digit code, hash-only, 15-minute
  expiry, 5-attempt lock, resend, live status. Consent sign requires a
  verified email. Password reset via the same code flow. Photos
  downscale in the browser (max 1200px JPEG 0.82) before upload.
- **Jobs For You** (v8) — evolved ranked match feed per talent, each job
  carrying its personal per-(talent, job) reference code.
- **Automation** (v8) — one BIG toggle per talent (agency-send email
  route: agency mailbox sends, talent CC'd, Reply-To the talent) plus
  fine rules in Fast-Track. TEST MODE: even ON, nothing is ever sent.
- **Proof of work + earnings** (v9) — completed jobs appear as credits
  in the talent's profile; talent sees ONLY their own net per job +
  running total. Agency commission is never in the talent payload.
- **Owner gate** (v10) — owner passcode → 12-hour session token; Agency
  Earnings (commission totals + per-agency breakdown) renders ONLY for
  a verified owner (or the admin token). Everyone else gets 401.
- **Personal portfolio links** (v11) — every talent gets `#/talent/<id>`,
  a public page for THAT person (never the front page), gated by
  visibility (private by default, agency-staff-only, or public) and a
  separate share-photos switch. Casting-safe fields only: no email,
  phone, demographics, zip, fees, or earnings, ever.
- **Social links** (v11) — a talent links THEIR OWN Instagram/Facebook
  (talent-attested: begin → confirm; bio-checked flag) and adds a few
  of their social photos as an extended portfolio preview. No OAuth
  integration yet — that is a later build, stated on the screen.
- **Likeness Release & Representation Consent** — contract text, checkbox +
  typed e-signature (must match the legal/professional name), agency review
  gate (PASS/FAIL with reason) → READY FOR MATCHING.
- **Pay-first rotation engine** — ranks by normalized daily pay, blocks
  overlapping times at different locations, same-address clusters allowed,
  caps 3/day and 10/week. Selected jobs queue AWAITING APPROVAL.
- **Bookings** — evidence required; full gross / fee / net breakdown to the
  cent. Commission is automatic on a 10–15% sliding scale (10% at $100/day,
  15% at $1,000/day, linear between). Calculated and tracked only — never
  collected. Booking emails stay QUEUED (email integration not connected).
- **Cubicles + inbound replies** — staff can create cubicles and set
  their status (`#/cubicles`); agency/casting replies to an
  application are recorded by staff and visible to the talent
  (`#/replies`, `POST /api/v1/application-replies` admin-only).
- **Ledger** — append-only, hash-chained record of every event (registrations,
  consent, reviews, matches, applications, bookings, payments, ingestions).
  `GET /api/v1/ledger/verify` recomputes the chain. Ledger view + contact
  book in the UI.
- **Community Board (v16, Phase 0 — `#/community`).** One public board:
  everybody sees everybody's posts; there are no private DMs. Text + one
  photo per post (JPG/PNG/WEBP, 500KB decoded cap, bytes in SQLite like
  portfolio photos). @ mentions autocomplete live (narrowing per letter,
  tap to insert), are stored as talent ids, highlighted to the named
  person, and delivered as an in-app notification. The direct-talk bubble
  is only a filtered view of the same public posts — it says so in its
  header — and closes on "End chat" or 30 seconds after the last typing;
  the messages stay on the board. Talent deletes own posts; the owner
  removes any post behind the owner gate; reports are recorded for owner
  review with no automated action. Every board action is ledger-recorded
  (`BOARD_POST_CREATED`, `BOARD_MENTION_DELIVERED`, `BOARD_POST_REPORTED`,
  `BOARD_POST_DELETED`, `BOARD_POST_REMOVED_BY_OWNER`). Audio and carousel
  posts are refused honestly ("coming soon") and create nothing — not
  implemented in this phase. Composer keeps native autocorrect/predictive
  text enabled. **Honest limit:** board posts and photo bytes live in the
  same ephemeral SQLite as everything else; the mirror carries the board
  ledger events (ids + counts only, never post bodies or photo bytes),
  not the posts themselves — a full restart wipes board posts, same as
  portfolio photos (see MIRROR.md).
- **Recurring-agency monitor** — agencies ranked by booking volume, TOP REPEAT
  AGENCY badges at/above the threshold (default 3 confirmed bookings) or in
  the top 10% by booking volume (both configurable in settings), spike
  flags, full history one click away. Manual ledger notes (corrections) are
  appended as new entries, never edits to history.
- **Opening splash + brand mark** — the first thing seen is the logo: a golden
  teacup topped with a crown (TOP = crown, TEA = cup), steam rising, rendered
  in 2.8D (gold gradients, layered shadows, subtle bevel). The splash fades
  on its own in ~2.4s or on tap, shows once per browser session, and has an
  inline failsafe so it can never trap the user. The same mark is the
  persistent brand in the header, the home hero, and the sign-up screens.
- **Browse All Listings** (`#/browse`) — one scrollable list of all 423
  listings, newest first by default (oldest-first option), with filters for
  geography, county, category, pay type, verification status, source,
  keyword, and a live/expired toggle. Expired listings are dimmed with an
  EXPIRED badge, never shown as live. "Date listed" is the date the listing
  was discovered — the source boards gave no per-listing posted date.
  API: `GET /api/v1/opportunities?status=live|expired|all&sort=newest|oldest
  &pay_type=&source=&county=&geography=&category=&verification_status=&q=`.

## Version

- **Artifact parity: v16.** The footer carries a visible stamp
  (`TOP TEA TALENTS • v16 • updated <date>`, from
  `window.__TTT_BUILD__` in `frontend/index.html`), and
  `/api/v1/health` reports the backend version (`1.1.0`). If the stamp
  and the artifact disagree, the package is stale — that is the drift
  check. v16 ports the artifact's Community Board (Phase 0) plus the
  returning-account wizard resume fix (WELCOME BACK panel on join step 1
  for a signed-in talent; "Sign in instead" link on the
  already-registered error). Backend version stays 1.1.0.

## Social linking + Instagram auto-pull — what is real here (v12–v14)

- **v12 — per-talent social linking.** A talent links THEIR OWN
  Instagram/Facebook: begin issues a unique ownership code, the talent
  puts it in their bio, then signs (typed name must match the profile,
  same standard as the Likeness Release). Preview photos are uploads
  with the link to the original post on the talent's own AUTHORIZED
  account, so every photo is traceable to the talent's own post.
- **v13 — authorization-state hardening.** An account is AUTHORIZED
  only when the live bio check confirmed the code
  (`verificationStatus: "code_confirmed"`). Signing never authorizes
  by itself. Any record reading AUTHORIZED without a confirmed code is
  demoted to pending on read (and at boot migration), with the reason
  recorded — it can never stay authorized.
- **v14 — Instagram auto-pull: HONEST LIMIT.** The artifact pulls a
  talent's first three Instagram photos plus their most popular post
  by dispatching a browser task that visits the public profile
  signed-out and face-matches each snapshot against the portfolio.
  **This standalone public site has no background-task dispatch, so it
  cannot run that pull.** A pull request here is recorded as
  `pullStatus: "unavailable"` with the reason shown in the UI — never
  faked. What IS ported: the full pull state model, the admin pull
  callback (`POST /api/v1/social-photo-pull-callback`, admin token
  only) that places only identity-matched photos (`identity_verdict:
  "match"`, max 4; everything else is counted rejected, never shown),
  and the honest UI note on the Social page. The pull itself runs
  from the agency app, which reports back through the callback.
- **Bio check, same adaptation.** The live bio check is also
  dispatched from the agency app. The standalone reports its outcome
  through the admin bio-check route
  (`POST /api/v1/talent/:id/social-links/:linkId` with
  `{"action":"bio-check","outcome":"found"|"not_found"|"unreadable"}`,
  admin token only) — same precedent as the staff-marked email
  dispatch (`auth/mark-email-verification-dispatched`). A talent token
  can never call it; a wrong admin token is refused (401).

## Run locally

```bash
cd server
bun install            # dev types only; runtime has zero npm dependencies
PORT=3101 DATABASE_PATH=/tmp/ttt.db ADMIN_TOKEN=dev-token bun run src/server.ts
# in another shell, serve the frontend with the API pointed at it:
#   echo 'window.__TTT_API__ = "http://localhost:3101";' > ../frontend/api-config.js
#   python3 -m http.server 8123 --directory ../frontend
bash server/selftest.sh   # 136 checks, boots its own temp DB
bun x tsc --noEmit -p server/tsconfig.json
```

First boot lazy-seeds the bundled data (one `seed.import` ledger event).
Admin re-seed: `POST /api/v1/admin/seed` with the admin token.

## Environment (Render)

| Variable | Notes |
|---|---|
| `ADMIN_TOKEN` | Generated by Render (`generateValue`) — read it in the Render dashboard; it authorizes admin calls (review, settings, bookings). |
| `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` | Set these for durable storage. Without them the API runs on local SQLite and **loses all sign-ups on every restart** — the health endpoint reports `storage_durable: false` honestly. |
| `DATABASE_PATH` | SQLite file path when Turso is not set (default `/data/top-tea-talents.db`). |
| `PUBLIC_URL` | Public API URL, used in health output. |
